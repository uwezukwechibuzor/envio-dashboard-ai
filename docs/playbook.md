# Envio Dashboard AI — Sales & Success Playbook

For Envio growth and sales. Use this to run a live 5-minute demo, turn the generated dashboard into a HyperIndex PoC, and hand off to the protocol team.

---

## 1. The 5-minute prospect demo

**Setup (30 seconds before the call):**
1. Open [envio-dashboard.ai](https://envio-dashboard.ai) in an incognito window.
2. Confirm the page loads. That's it — no login required for the demo.

**On the call:**

> "Let me show you something. What protocol are you working on?"

Type their answer into the prompt box — verbatim. For example:

> "Generate me a Uniswap V3 dashboard on Arbitrum: fees, volume, and transactions for the last 90 days"

**What to say while it generates (~10–20 seconds):**

> "It's querying HyperSync right now — Envio's raw blockchain data infrastructure. No subgraph, no deployment, no waiting. It backfills 90 days of on-chain data live."

**When the dashboard appears:**

> "Every number here is live and re-queried each time you open the link. This is not a snapshot — it's the protocol's actual chain state. Here's the share link."

Point to: volume KPI, the daily chart, the freshness badge ("data as of block N / 2 min ago").

**The upsell moment:**

Scroll to the Envio upsell panel at the bottom:

> "Now here's the interesting part. This same dashboard can become your own production indexer. One command — `envio init contract-import` — and you have a full HyperIndex project with handlers for every event we just queried. You deploy it to Envio Cloud and it's yours: your own API, your own schema, your own query layer. No vendor lock-in."

## 2. Discovery questions

Use these to qualify the prospect and understand their needs:

**Data questions:**
- What data are you querying today? (The Graph subgraph? Custom indexer? Direct RPC?)
- How long does a full re-index take when you change something?
- What chains are you on? Do you need cross-chain aggregation?

**Pain questions:**
- Has your subgraph ever lagged behind the chain? How did you find out?
- What does it cost you today to run your indexer? (hosting, dev time)
- Have you needed to add a new event to your indexer recently? How long did it take?

**Goal questions:**
- Who uses your analytics? Internal team? Public dashboard? Investors?
- Do you have a data analyst or is it engineers all the way down?
- Is there a specific metric you've never been able to compute because it was too complex?

## 3. From dashboard to HyperIndex PoC (15-minute handoff)

After the demo, follow this sequence to give the prospect a working indexer:

**Step 1: Get the `envio init` command from the upsell panel.**

The panel shows the exact command tailored to their protocol:

```bash
envio init contract-import
```

It will prompt for the contract address, chain, and start block — all visible in the dashboard.

**Step 2: Walk them through the generated project structure:**

```
my-indexer/
  schema.graphql    ← the data model (edit this to add fields)
  src/EventHandlers.ts  ← one handler per event (edit this to compute metrics)
  config.yaml       ← network + contract config (auto-generated)
```

**Step 3: Show the handler pattern** (takes 2 minutes to explain):

```typescript
// EventHandlers.ts — generated by envio init
indexer.onEvent(SwapEvent, async ({ event, context }) => {
  // event.params contains the decoded event fields
  // context.entities gives you read/write access to your schema
  await context.entities.DailyVolume.set({
    id: `${event.chainId}_${event.block.date}`,
    volume: (event.params.amount0 < 0n
      ? -event.params.amount0
      : event.params.amount1 < 0n
      ? -event.params.amount1
      : 0n).toString(),
    date: event.block.date,
  });
});
```

> "This handler fires for every Swap event. You write the logic, Envio runs it at chain speed. The data is queryable via GraphQL the moment you deploy."

**Step 4: Deploy to Envio Cloud:**

```bash
envio deploy
```

> "One command, managed infrastructure. You get a hosted GraphQL endpoint, automatic re-indexing on code changes, and monitoring out of the box."

## 5. Objection handling

**"We already have a subgraph."**
> "Totally — and you can keep it. This is for the analysis layer on top of it, or for the cases where your subgraph doesn't expose what you need. HyperSync can backfill 90 days of data that your subgraph would need days to re-index."

**"We use Dune / Flipside / Nansen."**
> "Those are great for ad-hoc queries. This is for production dashboards you embed in your app, plus an indexer you own and deploy. And it's live — not query-time aggregation."

**"This is too early / we don't have time."**
> "Fair. The indexer side takes real time. The dashboard side takes literally 20 seconds — it's a URL you can share with your investors this afternoon. Want me to generate one for your protocol right now and send you the link?"

**"We need historical data beyond what the dashboard shows."**
> "HyperSync goes back to genesis on most chains. The dashboard defaults to 90 days for the demo, but the API and your own indexer have no limit."

## 6. What makes a great demo protocol

Best protocols for the demo (all have good data, familiar to the audience):

| Protocol | Prompt | Why it works |
|---|---|---|
| Uniswap V3 | "Uniswap V3 fees and volume on Arbitrum last 90 days" | Instant name recognition, impressive numbers |
| Aave V3 | "Aave V3 borrow volume on Ethereum last 30 days" | Simple to explain, big TVL |
| The prospect's own protocol | "[Their protocol] on [their chain]" | Most impactful — it's their data |

**Avoid for the demo:**
- Very new protocols (may not be in a pack yet)
- L2-only protocols with low volume (numbers look unimpressive)
- Cross-chain comparison on first view (save for follow-up)
